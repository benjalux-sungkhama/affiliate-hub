# ระบบโพสต์อัตโนมัติ (Automation Rules) — คู่มือใช้งานจริง

อิงสเปกเต็มที่อัปโหลด (§1–§12 + ผ.ก. A/B) และแมปกับโค้ดในโปรเจกต์นี้
เมนู: **ระบบอัตโนมัติ** (`automation.php`)

> หลักคิด: อัตโนมัติ = ลดงานซ้ำ ไม่ใช่ปล่อยมือ — ทุกกฎมีเพดานและปุ่มหยุด

## สายพาน
```
ทริกเกอร์ยิง → เช็กเงื่อนไข → AI สร้างจากสูตร → เข้าคิว/รออนุมัติ → โพสต์ + เก็บสถิติ
```
ทุกกฎ **ต้องผูกสูตร** จากคลังสูตร (`formula_id`) — Automation ไม่สร้าง Prompt เอง

## โครงสร้างกฎ (Trigger → Condition → Action)
| ส่วน | ที่กรอกในหน้าเว็บ |
|---|---|
| ชื่อกฎ / คำอธิบาย | ช่องข้อความ |
| ทริกเกอร์ | dropdown (schedule.* / product.* / post.* / order.* / live.* / formula.*) |
| เงื่อนไข | JSON เช่น `[{"field":"product.profit","op":">=","value":80}]` |
| สูตรที่ใช้ | dropdown สูตรของคุณ |
| ปลายทาง + หน่วงเวลา | ช่องแพลตฟอร์ม + นาที |
| โหมดอนุมัติ | Draft / Review / Auto |

**op ที่รับได้:** `=` `!=` `>` `>=` `<` `<=` `between` `in` `not_in` `contains`
**field ที่มีให้:** `product.category` `product.price` `product.profit` `product.stock` `product.image_count` `time.hour` `time.dow` `order.count` ฯลฯ

## โหมดอนุมัติ 3 แบบ (§6)
| โหมด | พฤติกรรม |
|---|---|
| 🟢 Draft | สร้างเป็นโพสต์ร่าง ไม่โพสต์ |
| 🟡 Review | เข้าคิว **รออนุมัติ** (แท็บ "รออนุมัติ") กด ✅ ถึงเข้าคิวโพสต์ |
| 🔴 Auto | สร้าง + เข้าคิวโพสต์เอง (ผ่าน Guardrails) |

กฎใหม่ทุกกฎ **ถูกบังคับเริ่มที่ Draft + ปิดอยู่** เปลี่ยนโหมด/เปิดสวิตช์เองภายหลัง

## Guardrails ระดับบัญชี (§7) — แท็บ "ตั้งค่า Guardrails"
- เพดานโพสต์อัตโนมัติ/วัน (ค่าเริ่มต้น 8)
- ช่วงเวลาห้ามโพสต์ (23:00–07:00)
- กันสินค้าซ้ำ (7 วัน) · เพดานเรียก AI/วัน (30)
- ล้มเหลว 3 ครั้งติด → ปิดกฎอัตโนมัติ (ล็อกตามสเปก)
- 🔴 **Kill Switch** — ปุ่มหยุดทุกกฎทันทีทั้งบัญชี

## แท็บในหน้า (§9)
กฎทั้งหมด · รออนุมัติ · ประวัติการทำงาน · สูตรสำเร็จ (Blueprint 6 แบบ) · ตั้งค่า Guardrails
- **▶️ ทดลองรัน (Dry Run)** — รันจริงแต่ไม่โพสต์ ดูว่าคอนเทนต์ออกมาหน้าตาไหน
- **รันเดี๋ยวนี้** — บังคับยิงทันที (ใช้สินค้าสุ่มเป็น context)
- **ส่งออก/นำเข้า JSON** — ตามสคีมาใน ผ.ก. A

## Worker และ Cron (§10)
ทริกเกอร์แบบ **เวลา** (schedule.*) ทำงานโดย `cron/automation_worker.php`
ทริกเกอร์แบบ **เหตุการณ์** (product.* / order.* / live.*) ยิงทันทีจากหน้าเว็บ

**Windows (Task Scheduler)** — เรียกทุก 5 นาที:
```
โปรแกรม:   C:\xampp\php\php.exe
อาร์กิวเมนต์: C:\xampp\htdocs\affiliatehub\cron\automation_worker.php
```
**macOS / Linux (crontab):**
```bash
*/5 * * * * /Applications/XAMPP/bin/php /Applications/XAMPP/htdocs/affiliatehub/cron/automation_worker.php >> /tmp/ahub_cron.log 2>&1
```
Worker: ล็อกกันรันซ้อน · สูงสุด 10 งาน/รอบ · บันทึกทุก run · error แล้วไปต่อ

> โพสต์ที่เข้าคิว (queued) จะถูกเผยแพร่จริงโดย `cron/scheduler.php` ตามโหมด off/simulate/live
> (ดู docs/AUTOMATION.md) — Automation Rules สร้างคิว, Scheduler เป็นคนโพสต์

## ตารางฐานข้อมูล (§11)
`automation_rules` · `automation_runs` · `automation_approvals` · `automation_settings`
ทุกตารางมี `user_id` · `automation_rules.formula_id` → FK `content_formulas` แบบ **ON DELETE RESTRICT**
(ลบสูตรที่กฎใช้อยู่ไม่ได้)

ติดตั้งย้อนหลังบน DB เดิม: phpMyAdmin → Import `sql/automation.sql`
(ฐานข้อมูลใหม่มีอยู่ใน `sql/schema.sql` แล้ว)

## Blueprint สำเร็จรูป 6 แบบ (§8)
สินค้าใหม่เข้า · สต๊อกใกล้หมด · โพสต์ที่ปังทำซ้ำ · ปั๊มก่อนไลฟ์ · คอนเทนต์ประจำวัน · สรุปหลังไลฟ์
กดติดตั้งได้จากแท็บ "สูตรสำเร็จ" (ติดตั้งเป็น Draft ปิดอยู่ ผูกสูตรค่าเริ่มต้นในคลัง)

## เช็กลิสต์ก่อนเปิด Auto (ผ.ก. B)
Review ≥ 14 วัน · อัตราอนุมัติไม่แก้ > 80% · ไม่เคยผิดสินค้า · ตัวแปร `{{ }}` เติมครบทุกครั้ง ·
ตั้งเพดาน/ช่วงห้ามโพสต์แล้ว · ทดสอบ Kill Switch · มีคนดู "ประวัติการทำงาน" ทุกวัน

## หมายเหตุการออกแบบในโปรเจกต์นี้
- ทริกเกอร์เหตุการณ์ยิง **ในคำขอเดียวกัน** ที่เกิดเหตุ (เพิ่มสินค้า/ออเดอร์/ไลฟ์) แทนตารางคิวแยก
  — เชื่อถือได้และคงจำนวนตารางไว้ที่ 4 ตามสเปก §11
- ถ้าตัวแปร `{{ }}` ในสูตรเติมค่าไม่ครบ กฎจะ **หยุดและบันทึก failed** ไม่โพสต์ทิ้งค่าว่าง (§5)
  → กฎ order.milestone / live.ended ควรใช้สูตรที่ไม่พึ่งตัวแปรสินค้า (เช่น ไม่มี `{{price}}`)
