## §1 ภาพรวมและคำศัพท์

ระบบทำงานเป็นสายพาน 5 ขั้น:

```
ทริกเกอร์ยิง → เช็กเงื่อนไข → AI สร้างจากสูตร → เข้าคิว/รออนุมัติ → โพสต์ + เก็บสถิติ
```

| คำ | ความหมาย |
|---|---|
| **Rule (กฎ)** | ชุดคำสั่ง 1 ชุด = 1 แถวใน `automation_rules` |
| **Trigger** | ตัวจุดชนวน — เวลา หรือเหตุการณ์ |
| **Condition** | ด่านกรอง ถ้าไม่ผ่าน กฎจะข้ามรอบนั้น |
| **Action** | สิ่งที่ทำ — สร้างคอนเทนต์ เข้าคิว โพสต์ แจ้งเตือน |
| **Run** | การทำงาน 1 รอบของกฎ = 1 แถวใน `automation_runs` |
| **Blueprint** | กฎสำเร็จรูปที่กดติดตั้งได้เลย |
| **Kill Switch** | ปุ่มหยุดทุกกฎทันทีทั้งบัญชี |

**เชื่อมกับคลังสูตร:** ทุกกฎต้องผูก `formula_id` เสมอ — Automation ไม่สร้าง Prompt เอง แต่หยิบสูตรจากคลัง (ดู `marketing.md` §3.3)

## §2 โครงสร้างกฎ

ทุกกฎประกอบด้วย 6 ส่วน กรอกครบถึงจะเปิดใช้งานได้:

| ส่วน | บังคับ | ตัวอย่าง |
|---|---|---|
| ชื่อกฎ | ✅ | "สินค้าใหม่เข้า โพสต์ TikTok ทันที" |
| ทริกเกอร์ | ✅ | `product.created` |
| เงื่อนไข | ❌ | หมวด = ไฟฉาย, ราคา > 300 |
| สูตรที่ใช้ | ✅ | สูตร "Storyboard 10 วิ 6 ซีน" |
| ปลายทาง | ✅ | TikTok + Facebook |
| โหมดอนุมัติ | ✅ | Review |

## §3 ทริกเกอร์ทั้งหมด

### 3.1 แบบตามเวลา (Schedule)

| ทริกเกอร์ | ยิงเมื่อ | ใช้กับ |
|---|---|---|
| `schedule.daily` | ทุกวันเวลาที่กำหนด | โพสต์ประจำวัน |
| `schedule.weekly` | เลือกวันในสัปดาห์ | คอนเทนต์รายสัปดาห์ |
| `schedule.interval` | ทุก N ชั่วโมง | ปั๊มคอนเทนต์ถี่ |
| `schedule.before_live` | ก่อนไลฟ์ N ชม. | โปรโมตไลฟ์ล่วงหน้า |

### 3.2 แบบตามเหตุการณ์ (Event)

| ทริกเกอร์ | ยิงเมื่อ | ใช้กับ |
|---|---|---|
| `product.created` | เพิ่มสินค้าใหม่ | เปิดตัวสินค้า |
| `product.price_changed` | ราคาเปลี่ยน | ประกาศลดราคา |
| `product.low_stock` | สต๊อกต่ำกว่าเกณฑ์ | เร่งระบายของ |
| `product.restocked` | เติมสต๊อกกลับมา | ประกาศของเข้า |
| `post.high_performing` | โพสต์เก่าทะลุเกณฑ์ | ทำเวอร์ชันใหม่ซ้ำ |
| `order.milestone` | ยอดขายถึงหมุดหมาย | คอนเทนต์ Social Proof |
| `live.ended` | ไลฟ์จบ | สรุปไลฟ์ + ตัดคลิป |
| `formula.updated` | สูตรถูกแก้ | ทดสอบสูตรใหม่ |

> ทริกเกอร์เหตุการณ์ยิงผ่านตารางคิว ไม่ยิงทันทีในทันที — Worker จะหยิบภายใน 5 นาที

## §4 เงื่อนไข

รวมกันได้หลายข้อ ทั้งหมดต้องเป็นจริงพร้อมกัน (AND)

| ประเภท | ตัวอย่าง |
|---|---|
| สินค้า | หมวด, ราคาขาย, กำไรขั้นต่ำ, มีรูปครบ, สต๊อก > 0 |
| เวลา | เฉพาะ 09:00–21:00, ไม่โพสต์วันอาทิตย์ |
| ผลงาน | โพสต์ต้นทางมี Reach > 5,000 หรือ CTR > 3% |
| โควตา | วันนี้กฎนี้ยังยิงไม่เกิน N ครั้ง |
| ซ้ำ | สินค้าชิ้นนี้ยังไม่ถูกโพสต์ใน 7 วันล่าสุด |

**ตัวอย่างชุดเงื่อนไข:**
```
หมวด = ไฟฉาย
AND กำไรต่อชิ้น >= 80 บาท
AND สต๊อก >= 10
AND ไม่เคยโพสต์สินค้านี้ใน 7 วัน
AND เวลาปัจจุบันอยู่ใน 09:00–21:00
```

## §5 แอ็กชัน

| แอ็กชัน | ทำอะไร |
|---|---|
| `generate_content` | เรียก AI สร้างคอนเทนต์จากสูตรที่ผูกไว้ |
| `enqueue_post` | ส่งเข้าคิวโพสต์ตามช่วงเวลาที่กำหนด |
| `publish_now` | โพสต์ทันที (ต้องโหมด Auto เท่านั้น) |
| `create_draft` | บันทึกเป็นร่าง ไม่เข้าคิว |
| `notify` | แจ้งเตือนในระบบ / อีเมล |
| `log_only` | บันทึกอย่างเดียว ใช้ทดสอบกฎ |

**ลำดับมาตรฐาน:** `generate_content` → `enqueue_post` → `notify`

**การเติมตัวแปร:** ระบบเติม `{{ }}` จากข้อมูลสินค้าที่ทริกเกอร์ให้มาโดยอัตโนมัติ ถ้ามีตัวแปรหาค่าไม่เจอ → กฎจะ **หยุดและแจ้งเตือน** ไม่โพสต์ทิ้งค่าว่าง

## §6 โหมดอนุมัติ 3 แบบ

| โหมด | พฤติกรรม | เหมาะกับ |
|---|---|---|
| 🟢 **Draft** | สร้างแล้วเก็บเป็นร่างเฉย ๆ | ทดลองกฎใหม่ |
| 🟡 **Review** | เข้าคิวรออนุมัติ กด ✅ ถึงโพสต์ | ใช้งานจริงทั่วไป **(แนะนำ)** |
| 🔴 **Auto** | สร้างแล้วโพสต์เองเลย | กฎที่พิสูจน์แล้ว 2 สัปดาห์ |

**เส้นทางที่ปลอดภัย:** Draft 3 วัน → Review 2 สัปดาห์ → ค่อยเปิด Auto

> กฎใหม่ทุกกฎถูกบังคับให้เริ่มที่ Draft — ระบบไม่อนุญาตให้สร้างกฎแล้วเปิด Auto ทันที

## §7 Guardrails กันพัง

| กติกา | ค่าเริ่มต้น | ปรับได้ |
|---|---|---|
| เพดานโพสต์อัตโนมัติต่อวัน | 8 โพสต์/บัญชี | ✅ |
| เว้นระยะขั้นต่ำระหว่างโพสต์ | 90 นาที | ✅ |
| กันคอนเทนต์ซ้ำ | เทียบความเหมือน > 85% → ทิ้ง | ✅ |
| กันสินค้าซ้ำ | สินค้าเดิมเว้น 7 วัน | ✅ |
| เพดานเรียก AI ต่อวัน | 30 ครั้ง | ✅ |
| หยุดกฎอัตโนมัติเมื่อล้มเหลว | ล้มเหลว 3 ครั้งติด → ปิดกฎ + แจ้งเตือน | ❌ |
| ช่วงเวลาห้ามโพสต์ | 23:00–07:00 | ✅ |
| **Kill Switch** | ปุ่มแดงบนหน้า Automation หยุดทุกกฎทันที | — |

> ⚠️ Guardrails ทำงานระดับ **บัญชี** ไม่ใช่ระดับกฎ — เปิด 5 กฎพร้อมกันก็ยังโพสต์รวมไม่เกินเพดานต่อวัน

## §8 สูตรสำเร็จ 6 แบบ

### 8.1 สินค้าใหม่เข้า โพสต์เปิดตัวทันที
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `product.created` |
| เงื่อนไข | มีรูป ≥ 3, ราคาขาย > 0, สต๊อก ≥ 5 |
| สูตร | Storyboard 10 วิ 6 ซีน |
| ปลายทาง | TikTok, Facebook |
| โหมด | Review |

### 8.2 สต๊อกใกล้หมด เร่งระบาย
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `product.low_stock` (< 10 ชิ้น) |
| เงื่อนไข | ยังไม่เคยยิงกฎนี้กับสินค้านี้ใน 3 วัน |
| สูตร | เร่งด่วน/ของใกล้หมด |
| โหมด | Review |

### 8.3 โพสต์ที่ปัง ทำซ้ำอีกเวอร์ชัน
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `post.high_performing` |
| เงื่อนไข | Reach > 10,000 **และ** โพสต์อายุ ≥ 14 วัน |
| สูตร | ใช้สูตรเดิมของโพสต์นั้น (`inherit_formula`) |
| โหมด | Review |

### 8.4 ปั๊มโปรโมตก่อนไลฟ์
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `schedule.before_live` (24 ชม. / 3 ชม. / 30 นาที) |
| แอ็กชัน | สร้าง 3 โพสต์ต่างมุม |
| โหมด | Review |

### 8.5 คอนเทนต์ประจำวัน
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `schedule.daily` 10:00 |
| เงื่อนไข | สุ่มสินค้าที่กำไร ≥ 80 บาท และไม่ซ้ำ 7 วัน |
| สูตร | สูตร Default ของหมวดนั้น |
| โหมด | Review |

### 8.6 สรุปหลังไลฟ์
| ช่อง | ค่า |
|---|---|
| ทริกเกอร์ | `live.ended` |
| แอ็กชัน | สรุปยอด + สินค้าขายดี 3 อันดับ → โพสต์ขอบคุณ |
| โหมด | Review |

## §9 หน้าจอและปุ่ม

**เมนู: ระบบอัตโนมัติ**

| แท็บ | มีอะไร |
|---|---|
| กฎทั้งหมด | ตารางกฎ + สวิตช์เปิดปิด + สถานะล่าสุด |
| รออนุมัติ | คอนเทนต์ที่รอกด ✅ / ✏️ แก้ / ❌ ทิ้ง |
| ประวัติการทำงาน | ทุก Run พร้อมผลลัพธ์และเหตุผลที่ข้าม |
| สูตรสำเร็จ | Blueprint กดติดตั้ง 6 แบบ |
| ตั้งค่า Guardrails | เพดาน/ช่วงเวลา/Kill Switch |

**ตารางกฎแสดง:** ชื่อกฎ · ทริกเกอร์ · สูตรที่ใช้ · โหมด · ยิงล่าสุด · สำเร็จ/ล้มเหลว · สวิตช์

**ปุ่มสำคัญ:** ▶️ ทดลองรัน (Dry Run) — รันจริงแต่ไม่โพสต์ ใช้ดูว่าคอนเทนต์ออกมาหน้าตาไหน

## §10 Worker และ Cron

Worker ทำงานทุก **5 นาที** หยิบงานที่ถึงกำหนดมาประมวลผล

**Windows (Task Scheduler):**
```
โปรแกรม: C:\xampp\php\php.exe
อาร์กิวเมนต์: C:\xampp\htdocs\affiliatehub\cron\automation_worker.php
ทำซ้ำ: ทุก 5 นาที
```

**macOS / Linux (crontab):**
```bash
*/5 * * * * /Applications/XAMPP/bin/php /Applications/XAMPP/htdocs/affiliatehub/cron/automation_worker.php >> /tmp/ahub_cron.log 2>&1
```

**กติกาของ Worker:**
- ล็อกกันรันซ้อน (lock file) — รอบก่อนยังไม่จบ รอบใหม่ข้าม
- 1 รอบทำงานได้สูงสุด 10 งาน กันเวลาบานปลาย
- ทุก Run บันทึกลง `automation_runs` เสมอ แม้ผลจะเป็น "ข้าม"
- เจอ error ให้บันทึกแล้วไปงานถัดไป ห้ามหยุดทั้งรอบ

> ไม่ตั้ง Cron ก็ใช้ได้ แต่กฎแบบเวลาจะไม่ยิงเอง — ต้องกด "รันเดี๋ยวนี้" เอง

## §11 ตารางฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `automation_rules` | กฎ + ทริกเกอร์ + เงื่อนไข (JSON) + `formula_id` + โหมด |
| `automation_runs` | ทุกรอบการทำงาน + ผลลัพธ์ + เหตุผลที่ข้าม |
| `automation_approvals` | คอนเทนต์ที่รออนุมัติ |
| `automation_settings` | Guardrails รายบัญชี + สถานะ Kill Switch |

ทุกตารางมี `user_id` และต้อง filter ด้วย `user_id` ทุก query
`automation_rules.formula_id` → FK ไป `content_formulas.id` แบบ `ON DELETE RESTRICT` (ลบสูตรที่กฎใช้อยู่ไม่ได้ ดู `troubleshooting.md` §6.6)

## §12 สถิติและรายงาน

**ต่อกฎ:** ยิงไปกี่ครั้ง · สำเร็จ/ข้าม/ล้มเหลว · โพสต์ที่เผยแพร่ · Reach รวม · ยอดขายที่ผูก

**ภาพรวม:** สัดส่วนโพสต์อัตโนมัติ vs โพสต์มือ · เวลาที่ประหยัดได้ (โดยประมาณ) · กฎที่คุ้มที่สุด 3 อันดับ

**ใช้ตัดสินใจ:** กฎไหนอัตราอนุมัติ > 80% ติดกัน 2 สัปดาห์ = พร้อมเลื่อนเป็นโหมด Auto

## ภาคผนวก A — JSON Schema ของกฎ

ใช้กับปุ่มส่งออก/นำเข้ากฎ

```json
{
  "name": "สินค้าใหม่เข้า โพสต์ TikTok",
  "description": "ยิงทันทีเมื่อเพิ่มสินค้าใหม่ที่มีรูปครบ",
  "trigger": {
    "type": "product.created",
    "config": {}
  },
  "conditions": [
    { "field": "product.image_count", "op": ">=", "value": 3 },
    { "field": "product.profit",      "op": ">=", "value": 80 },
    { "field": "product.stock",       "op": ">=", "value": 5 },
    { "field": "time.hour",           "op": "between", "value": [9, 21] }
  ],
  "formula_id": 12,
  "actions": [
    { "type": "generate_content", "config": { "variant_count": 1 } },
    { "type": "enqueue_post", "config": { "platforms": ["tiktok", "facebook"], "delay_minutes": 30 } },
    { "type": "notify", "config": { "channel": "in_app" } }
  ],
  "approval_mode": "review",
  "guardrails": {
    "max_runs_per_day": 3,
    "cooldown_days_per_product": 7
  },
  "is_active": false
}
```

**ฟิลด์บังคับ:** `name`, `trigger.type`, `formula_id`, `actions`, `approval_mode`
**ค่าที่รับได้ของ `op`:** `=`, `!=`, `>`, `>=`, `<`, `<=`, `between`, `in`, `not_in`, `contains`

## ภาคผนวก B — เช็กลิสต์ก่อนเปิดโหมด Auto

ครบ 8 ข้อค่อยเปิด:

- [ ] กฎนี้อยู่โหมด Review มาแล้วอย่างน้อย 14 วัน
- [ ] อัตราอนุมัติโดยไม่แก้ > 80%
- [ ] ไม่เคยสร้างคอนเทนต์ผิดสินค้า
- [ ] ตัวแปร `{{ }}` เติมครบทุกครั้ง ไม่มีค่าว่าง
- [ ] ตั้งเพดานต่อวันแล้ว
- [ ] ตั้งช่วงเวลาห้ามโพสต์แล้ว
- [ ] ทดสอบ Kill Switch ว่าหยุดได้จริง
- [ ] มีคนดูหน้า "ประวัติการทำงาน" อย่างน้อยวันละครั้ง
