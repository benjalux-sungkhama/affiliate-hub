## §1 ติดตั้งเครื่องมือ

### 1.1 `git` ไม่ใช่คำสั่งที่รู้จัก / command not found
1. ตรวจว่าติดตั้ง Git แล้วจริง — เปิด Git Bash หรือค้นหา "Git" ในเครื่อง
2. **ปิด Terminal / Command Prompt ทุกหน้าต่าง แล้วเปิดใหม่** — PATH อัปเดตเฉพาะ session ใหม่
3. **รีสตาร์ท Claude App** ด้วย (ถ้าสั่งผ่าน Claude)
4. ยังไม่ได้ → Windows: ติดตั้งซ้ำแล้วเลือก *"Git from the command line and also from 3rd-party software"*
5. macOS: `xcode-select --install`

### 1.2 Claude App มองไม่เห็นโฟลเดอร์โปรเจกต์
- ตรวจว่าชี้ path ถูก: `C:\xampp\htdocs\affiliatehub` หรือ `/Applications/XAMPP/htdocs/affiliatehub`
- โฟลเดอร์ต้องมีอยู่จริงก่อน (ทำ Phase 2 ให้จบ)
- ปิด-เปิด Claude App แล้วเลือกโฟลเดอร์ใหม่

### 1.3 ติดตั้ง XAMPP แล้วไม่มี PHP
- ตอนติดตั้งต้องติ๊ก **Apache + MySQL + PHP + phpMyAdmin** ครบ
- ติดตั้งซ้ำทับได้ ข้อมูลใน htdocs ไม่หาย (แต่สำรองไว้ก่อนอุ่นใจกว่า)

## §2 Apache / MySQL / Port

### 2.1 Apache Start ไม่ขึ้น (Port 80 ชน)
สาเหตุที่พบบ่อย: Skype, IIS, VMware, VPN, Windows World Wide Web Publishing Service

```bash
# Windows — หาว่าใครใช้ Port 80
netstat -ano | findstr :80
# เอา PID ที่ได้ไปดูใน Task Manager > Details

# macOS
sudo lsof -i :80
```

**ทางเลือกแก้:**
1. ปิดโปรแกรมที่ยึด Port 80
2. หรือย้าย Port ของ Apache → XAMPP → Config → `httpd.conf` → เปลี่ยน `Listen 80` เป็น `Listen 8080` และ `ServerName localhost:8080`
3. ถ้าย้าย Port แล้ว URL จะเป็น `http://localhost:8080/affiliatehub`

### 2.2 MySQL Start ไม่ขึ้น (Port 3306 ชน)
```bash
netstat -ano | findstr :3306   # Windows
sudo lsof -i :3306             # macOS
```
- มักเกิดจากมี MySQL/MariaDB ตัวอื่นติดตั้งไว้เป็น service
- Windows: `services.msc` → หา MySQL → Stop + ตั้งเป็น Manual
- หรือย้าย Port ใน `my.ini` → `port=3307` (ต้องแก้ `config.inc.php` ของ phpMyAdmin ตาม)

### 2.3 Apache ขึ้นแล้วดับเองใน 2 วินาที
- ดู Log ใน XAMPP → Apache → **Logs → error.log** บรรทัดล่างสุด
- สาเหตุบ่อย: syntax ผิดใน `httpd.conf` ที่เพิ่งแก้ → ย้อนกลับค่าเดิม

### 2.4 เข้า phpMyAdmin ไม่ได้
- MySQL ต้อง Start เขียวก่อน
- ลอง `http://127.0.0.1/phpmyadmin` แทน `localhost`
- ล้าง cache เบราว์เซอร์ หรือเปิดโหมดไม่ระบุตัวตน

## §3 โฟลเดอร์ ไฟล์ และสิทธิ์

### 3.1 macOS สร้างโฟลเดอร์ใน htdocs ไม่ได้
**เป็นเรื่องปกติของ macOS ไม่ใช่บั๊ก**
1. ให้ Claude สร้างโฟลเดอร์ให้แทน
2. หรือแก้สิทธิ์:
```bash
sudo chown -R $(whoami) /Applications/XAMPP/htdocs
sudo chmod -R 755 /Applications/XAMPP/htdocs
```

### 3.2 Windows เขียนไฟล์ไม่ได้ / Permission denied
- คลิกขวา XAMPP Control Panel → **Run as administrator**
- ตรวจว่า Antivirus ไม่ได้บล็อกโฟลเดอร์ htdocs

### 3.3 เปิดเว็บแล้วขึ้น 404 หรือ "Index of /affiliatehub"
| สาเหตุ | แก้ |
|---|---|
| ยังไม่มีไฟล์ `index.php` | รัน Prompt 4.2 ให้จบ |
| ชื่อโฟลเดอร์ไม่ตรง | ต้องเป็น `affiliatehub` ตัวเล็กทั้งหมด |
| วางโฟลเดอร์ผิดที่ | ต้องอยู่ใน `htdocs` ชั้นเดียว ไม่ซ้อนโฟลเดอร์ |

### 3.4 หน้าขาว (White Screen of Death)
1. เปิดแสดง error ชั่วคราว — ใส่บนสุดของไฟล์ที่พัง:
```php
ini_set('display_errors', 1);
error_reporting(E_ALL);
```
2. หรือดู `C:\xampp\apache\logs\error.log`
3. เอาข้อความ error ไปให้ Claude แก้ตรง ๆ

## §4 ฐานข้อมูลและตาราง

### 4.1 ชื่อฐานข้อมูลไม่ตรงกับโฟลเดอร์
ต้องตรงกันเป๊ะรวมตัวพิมพ์เล็ก-ใหญ่: โฟลเดอร์ `affiliatehub` → DB `affiliatehub`
ถ้าไม่ตรง ให้แก้ในไฟล์ config การเชื่อมต่อ หรือ Rename DB ใน phpMyAdmin (Operations → Rename)

### 4.2 `Access denied for user 'root'@'localhost'`
- XAMPP ค่าเริ่มต้น: user `root` รหัส **ว่าง**
- ถ้าเคยตั้งรหัสไว้ ต้องใส่ให้ตรงในไฟล์ config
- ลืมรหัส → รีเซ็ตผ่าน `mysqld --skip-grant-tables` (ให้ Claude ช่วยทีละขั้น)

### 4.3 `Table 'xxx' doesn't exist`
1. เช็กใน phpMyAdmin ว่าตารางนั้นถูกสร้างจริงไหม
2. ถ้าไม่มี → รัน Prompt 4.1 ซ้ำ (สั่งให้ใช้ `CREATE TABLE IF NOT EXISTS`)
3. ถ้าเป็นตาราง `content_formula*` → ดู §6.9

### 4.4 Foreign key constraint fails
- มักเกิดจากลำดับสร้างตารางผิด หรือลบแม่ทั้งที่ลูกยังอ้างอยู่
- ให้ Claude ตรวจลำดับ `CREATE TABLE` และเพิ่ม `ON DELETE CASCADE` ตามความเหมาะสม

### 4.5 อยากเริ่มใหม่ทั้งหมด
ดู **ภาคผนวก B** ใน `references/installation.md`
> ⚠️ ทำเฉพาะตอนยังไม่มีข้อมูลจริง และสำรอง SQL ไว้ก่อนเสมอ

## §5 สมัคร ล็อกอิน Access Code

### 5.1 ไม่มี Access Code
ต้องให้แอดมินสร้างให้ที่ **ตั้งค่า → รหัสเข้าใช้งาน → + สร้างรหัสใหม่**
ถ้าคุณเป็นคนติดตั้งเอง = คุณคือแอดมิน ให้สร้างรหัสแรกจากหน้านั้น

### 5.2 กรอก Access Code แล้วขึ้น "รหัสไม่ถูกต้อง"
| เช็ก | เกณฑ์ |
|---|---|
| ตัวพิมพ์เล็ก/ใหญ่ | ต้องตรงเป๊ะ |
| ช่องว่างติดมาตอนก๊อป | ลบออก |
| จำนวนครั้งที่ใช้ได้ | ต้องเหลือ > 0 |
| วันหมดอายุ | ต้องยังไม่ถึง |
| สถานะ | ต้องเป็น "เปิดใช้งาน" |

### 5.3 ล็อกอินแล้วเด้งกลับหน้าล็อกอิน
- Session ไม่ทำงาน → ตรวจโฟลเดอร์ `tmp` ของ PHP ว่าเขียนได้
- ตรวจว่า `session_start()` ถูกเรียกก่อน output ทุกหน้า

### 5.4 ลืมรหัสผ่าน
ใช้หน้า "ลืมรหัสผ่าน" หรือให้แอดมินรีเซ็ตให้ในหน้าจัดการผู้ใช้

### 5.5 เห็นข้อมูลของคนอื่น
**ถือเป็นบั๊กร้ายแรง** — แจ้งทันที
สาเหตุ: บาง query ลืม `WHERE user_id = ?`
แก้: สั่ง Claude "ตรวจทุก query ในระบบว่า filter ด้วย user_id ครบทุกตารางที่มีคอลัมน์นี้"

## §6 คลังสูตร (Content Formulas)

> อ้างอิงฟีเจอร์: `references/marketing.md` §3.3–3.4
> อ้างอิงการติดตั้ง: `references/installation.md` Prompt 4.4b

### 6.1 ตัวแปร `{{ }}` ไม่เติมค่า — ขึ้นเป็นข้อความดิบ

**อาการ:** ผลลัพธ์ยังเห็น `{{product_name}}` หรือ `{{price}}` ตรง ๆ

| สาเหตุ | วิธีแก้ |
|---|---|
| พิมพ์วงเล็บผิด | ต้องเป็นปีกกาคู่ `{{ }}` ไม่ใช่ `{ }` หรือ `{{{ }}}` |
| มีช่องว่างข้างใน | ต้องเป็น `{{price}}` ไม่ใช่ `{{ price }}` |
| สะกดชื่อตัวแปรผิด | ใช้ได้เฉพาะ 6 ตัวใน §3.3 เท่านั้น (ตัวเล็กทั้งหมด) |
| ไม่ได้เลือกสินค้าก่อนกดสร้าง | เลือกสินค้าในช่อง "เลือกสินค้า" ก่อนเสมอ |
| สินค้ายังไม่กรอกราคา | ไปเมนูสินค้า → กรอกราคาขาย |
| ระบบไม่ได้เรียก modal ถามค่า | ดู §6.2 |

**ตรวจเร็ว:** เปิดสูตร → ดูช่อง "ตัวแปรที่ใช้" ว่าตรงกับที่พิมพ์ในโครงซีนไหม

### 6.2 ไม่มี modal ถามค่าตัวแปรที่หาไม่เจอ
ตามสเปกระบบต้องเด้ง modal ถามก่อนสร้าง ถ้าไม่เด้ง = ตรรกะไม่ถูกสร้าง
```
ตรวจฟังก์ชันเติมตัวแปรในหน้าให้ AI คิดคอนเทนต์ของ AffiliateHub
ถ้ามีตัวแปร {{ }} ตัวใดหาค่าไม่เจอ ให้แสดง modal ถามผู้ใช้ก่อนส่ง Prompt ให้ AI
ห้ามส่งโดยปล่อยตัวแปรเป็นข้อความดิบหรือช่องว่าง
```

### 6.3 ส่งออก JSON แล้วไฟล์ว่าง / ดาวน์โหลดไม่ขึ้น
1. ตรวจว่าสูตรนั้นมีซีนอย่างน้อย 1 แถว
2. เช็ก error ใน Console ของเบราว์เซอร์ (F12)
3. สาเหตุบ่อย: มี output อื่นก่อน header ทำให้ไฟล์เสีย → ให้ Claude ตรวจว่าไม่มี `echo` ก่อน `header('Content-Disposition...')`

### 6.4 นำเข้า JSON ไม่ผ่าน

| ข้อความที่ขึ้น | สาเหตุ | แก้ |
|---|---|---|
| "รูปแบบไฟล์ไม่ถูกต้อง" | ไม่ใช่ JSON ที่ parse ได้ | เปิดไฟล์เช็กวงเล็บ/คอมมา ให้ครบ |
| "ไม่พบฟิลด์ name" | ขาดฟิลด์บังคับ | ต้องมีอย่างน้อย `name` + `category` |
| "ซีนไม่ถูกต้อง" | `scenes` ไม่ใช่ array หรือขาด `seq` | ทุกซีนต้องมี `seq` เป็นตัวเลข |
| ภาษาไทยเป็น `\u0e2a...` | ปกติ ไม่ใช่ error | ระบบถอดรหัสให้ตอนบันทึก |
| ภาษาไทยเป็น ??? หลังนำเข้า | ไฟล์ไม่ใช่ UTF-8 | บันทึกไฟล์ใหม่เป็น **UTF-8 without BOM** |
| นำเข้าแล้วเงียบ ไม่มีอะไรเกิด | ไฟล์ใหญ่เกิน `upload_max_filesize` | เพิ่มค่าใน `php.ini` แล้วรีสตาร์ท Apache |

**เช็กลิสต์ก่อนนำเข้า:**
- นามสกุลไฟล์ `.json`
- Encoding UTF-8 ไม่มี BOM
- โครงตรงกับตัวอย่างใน `marketing.md` ภาคผนวก A
- ไม่มีคอมมาเกินท้าย array (trailing comma)

### 6.5 นำเข้าแล้วชื่อสูตรซ้ำกับของเดิม
ระบบจะไม่ทับของเดิม แต่จะต่อท้ายว่า `(นำเข้า)` หรือ `(2)`
ถ้าอยากทับจริง ๆ ให้ลบสูตรเดิมก่อน แล้วนำเข้าใหม่

### 6.6 ลบสูตรไม่ได้

| ข้อความ | ความหมาย | ทางออก |
|---|---|---|
| "มีโพสต์ที่เข้าคิวอ้างอิงสูตรนี้อยู่" | มีโพสต์สถานะ **เข้าคิว** ผูกกับสูตร | ไปหน้าจัดคิว → ยกเลิก/เผยแพร่โพสต์นั้นก่อน แล้วค่อยลบ |
| "สูตรนี้เป็นค่าเริ่มต้นของหมวด" | ห้ามลบสูตร Default | ตั้งสูตรอื่นเป็นค่าเริ่มต้นก่อน |
| "สูตรนี้มีเวอร์ชันลูก" | มีสูตรที่ copy ต่อยอดไป | ลบลูกก่อน หรือกด **ปิดใช้งาน** แทนการลบ |
| กดยืนยันแล้วไม่หาย | ยืนยันไม่ครบ 2 ชั้น | ต้องกดยืนยันทั้งสองครั้ง |

> **แนะนำ:** ถ้าแค่ไม่อยากให้ขึ้นในตัวเลือก ใช้ **ปิดใช้งาน** แทนการลบ — ปลอดภัยกว่าและสถิติเดิมไม่หาย

### 6.7 บันทึกสูตรแล้วซีนหายไปบางแถว
- ซีนที่เว้น "เนื้อหา" ว่างจะถูกตัดทิ้งอัตโนมัติ → กรอกอย่างน้อยช่องเนื้อหา
- ลำดับ `seq` ซ้ำกันจะถูกรวม → กดปุ่มจัดลำดับใหม่ก่อนบันทึก
- ช่วงเวลาซ้อนทับกัน (เช่น 2 ซีนเริ่ม 3.4 พร้อมกัน) → ระบบเตือนแต่ยังบันทึกได้ ควรแก้ให้ต่อเนื่อง

### 6.8 กด "บันทึกเป็นสูตร" จากผลลัพธ์แล้วซีนไม่ถูกแยก
ระบบแปลงผลลัพธ์เป็นโครงซีนโดยอ่านบรรทัดที่ขึ้นต้นด้วย `ซีน N (เวลา–เวลา)`
- ถ้าผลลัพธ์ไม่ได้อยู่ในรูปแบบนี้ ระบบจะเก็บเป็นก้อนเดียว
- แก้: ให้ AI สร้างใหม่โดยยึดรูปแบบใน `marketing.md` §3.2 แล้วค่อยกดบันทึก
- หรือกดแก้ไขสูตรแล้วแยกซีนเองในฟอร์ม

### 6.9 ไม่เห็นแท็บ "คลังสูตรของฉัน"
แปลว่ายังไม่ได้รัน Prompt 4.4b
1. สำรองฐานข้อมูลก่อน (phpMyAdmin → Export → SQL)
2. เช็กว่ามีตารางหรือยัง:
```sql
SHOW TABLES LIKE 'content_formula%';
```
3. ถ้าไม่มี → รัน **Prompt 4.4b** ใน `references/installation.md`
4. รัน Smoke Test ข้อ 7–12

### 6.10 สถิติสูตรเป็น 0 ตลอด (ใช้ไปแล้ว / CTR / ยอดขาย)

| คอลัมน์ที่เป็น 0 | สาเหตุ | แก้ |
|---|---|---|
| ใช้ไปแล้ว | ไม่ได้บันทึกลง `content_formula_usages` | ให้ Claude ตรวจว่าปุ่ม "สร้างคอนเทนต์" เขียน log ทุกครั้ง |
| โพสต์ที่เผยแพร่ | โพสต์ไม่ได้เก็บ `formula_id` | ตรวจว่าตอนส่งเข้าคิวมีการบันทึก `formula_id` |
| Reach / CTR | ยังไม่ดึงสถิติจากแพลตฟอร์ม | ต้องเชื่อมบัญชีและรอข้อมูลกลับมา (§8) |
| ยอดขายที่ผูก | ออเดอร์ไม่ได้ผูกที่มาเป็นโพสต์ | เมนูคำสั่งซื้อ → เลือกที่มา = โพสต์นั้น |

### 6.11 ตั้งค่าเริ่มต้นแล้วสูตรอื่นยังถูกเลือกอยู่
- กฎคือ **หมวดละ 1 สูตร Default** — ถ้าตั้งซ้ำหลายอันแปลว่าตรรกะไม่ล้างของเดิม
```
แก้ตรรกะ is_default ในตาราง content_formulas ของ AffiliateHub
เมื่อผู้ใช้ตั้งสูตรใดเป็นค่าเริ่มต้น ให้ set is_default = 0
กับสูตรอื่นทั้งหมดของ user_id เดียวกันในหมวด (category) เดียวกันก่อนเสมอ
```
- ล้าง cache เบราว์เซอร์แล้วโหลดหน้าใหม่

### 6.12 ย้อนเวอร์ชันสูตรไม่ได้
- ระบบเก็บเวอร์ชันผ่าน `parent_id` + `version`
- ถ้าไม่มีปุ่มย้อนกลับ = ตอนแก้ไขระบบเขียนทับแทนที่จะสร้างเวอร์ชันใหม่
```
แก้การบันทึกสูตรใน AffiliateHub: เมื่อผู้ใช้แก้ไขสูตรที่มีอยู่แล้ว
ให้สร้างแถวใหม่ version + 1 โดยอ้าง parent_id เป็นสูตรต้นทาง
และเก็บแถวเดิมไว้ พร้อมปุ่ม "ย้อนกลับเวอร์ชันนี้" ในหน้าประวัติสูตร
```

### 6.13 สูตรของฉันหายไปหมด
1. ตรวจว่าล็อกอินด้วยบัญชีเดิม — สูตรผูกกับ `user_id`
2. ตรวจตัวกรองในตาราง (หมวด / สถานะเปิด-ปิด) → กด **ล้างตัวกรอง**
3. ถ้าเผลอปิดใช้งาน → เปิดตัวกรอง "แสดงที่ปิดใช้งานด้วย"
4. เช็กในฐานข้อมูลตรง ๆ:
```sql
SELECT id, name, category, is_active, version
FROM content_formulas WHERE user_id = [ไอดีของคุณ];
```
5. ถ้าข้อมูลหายจริง → กู้จากไฟล์สำรอง SQL ล่าสุด

## §7 AI คิดคอนเทนต์ / API Key

### 7.1 AI ไม่ตอบ / ขึ้น error เรื่อง API Key
| เช็ก | วิธี |
|---|---|
| กรอก Key แล้วหรือยัง | ตั้งค่า → โปรไฟล์ & การเชื่อมต่อ AI |
| Key ถูกต้อง | ก๊อปใหม่ ระวังช่องว่างท้าย |
| เครดิตเหลือ | ตรวจในบัญชีผู้ให้บริการ AI |
| อินเทอร์เน็ต | ลองเปิดเว็บอื่น |
| Firewall บล็อก | ปิดชั่วคราวเพื่อทดสอบ |

### 7.2 AI ตอบช้ามาก / timeout
- เพิ่ม `max_execution_time` ใน `php.ini` เป็น 120 แล้วรีสตาร์ท Apache
- ลดความยาว Prompt หรือแบ่งสร้างทีละส่วน

### 7.3 AI ส่งโครงเปล่ามาให้กรอกเอง
ผิดกติกา §3.4 — สั่งใหม่ว่า "เติมทุกช่องให้ครบตามข้อมูลสินค้าที่มี ห้ามเว้นว่าง"

## §8 โพสต์ คิว และการเชื่อมบัญชี

### 8.1 เชื่อมบัญชีไม่ผ่าน
- Token หมดอายุ → กด **เชื่อมใหม่**
- ถูกปฏิเสธสิทธิ์ → ตรวจว่าคุณเป็นแอดมินเพจ/ร้านนั้นจริง
- กด **ทดสอบการเชื่อมต่อ** ต้องขึ้น ✅ ก่อนบันทึกเสมอ

### 8.2 โพสต์ขึ้นสถานะ "ล้มเหลว"
1. เปิดคอลัมน์ **Log** อ่านเหตุผล
2. สาเหตุบ่อย: Token หมดอายุ, เกินโควตาต่อวัน, เนื้อหาผิดนโยบายแพลตฟอร์ม
3. แก้แล้วกด **ลองใหม่** (ได้ 3 ครั้ง)

### 8.3 โพสต์ไม่ขึ้นตามเวลาที่ตั้ง
- ตรวจโซนเวลาเป็น Asia/Bangkok
- ตรวจว่า Scheduler / Cron ทำงานอยู่
- ตรวจว่าไม่ชนกฎ "เว้นระยะขั้นต่ำ 90 นาที"

## §9 สินค้า ออเดอร์ กำไร

### 9.1 เพิ่มสินค้าไม่ได้
- ชื่อสินค้าและราคาขายเป็นฟิลด์บังคับ
- ราคาต้องเป็นตัวเลข ไม่ใส่คอมมาหรือสัญลักษณ์เงิน

### 9.2 กำไรขึ้นเป็น 0 หรือติดลบผิดปกติ
**สาเหตุอันดับ 1: ยังไม่กรอกต้นทุนในเมนูสินค้า**
1. เมนูสินค้า → แก้ไขสินค้า → กรอก **ต้นทุน**
2. ออเดอร์เก่าที่บันทึกก่อนกรอกต้นทุน ให้กด **คำนวณกำไรใหม่**
3. ติดลบ = ราคาขายต่ำกว่าต้นทุน + ค่าส่ง ตรวจว่ากรอกถูกไหม

### 9.3 ยอดขายไม่ผูกกับโพสต์/ไลฟ์
ต้องเลือก **ที่มาของยอดขาย** ตอนบันทึกออเดอร์ ถ้าลืมให้กลับไปแก้ออเดอร์นั้น

## §10 จัดส่ง COD รอบรถ ตีกลับ

### 10.1 สถานะพัสดุไม่อัปเดต
- ตรวจเลขพัสดุว่ากรอกถูก
- ระบบนี้เป็นการติดตามแบบบันทึกเอง — ต้องอัปเดตสถานะเมื่อมีข้อมูลจริง

### 10.2 ยอด COD ไม่ตรง
- ตรวจว่ากดยืนยัน **โอนเงินคืนร้าน** ครบทุกรายการ
- เทียบกับใบส่งมอบ (Manifest) ของรอบนั้น

### 10.3 สร้าง Manifest ไม่ได้
- ต้องมีออเดอร์สถานะ "พร้อมส่ง" อย่างน้อย 1 รายการ
- ต้องเลือกคนขับก่อนสร้าง

### 10.4 ของตีกลับแล้วสต๊อกไม่คืน
- ต้องบันทึกในเมนู **ตีกลับ & เซล** พร้อมระบุสาเหตุ ระบบถึงคืนสต๊อกอัตโนมัติ

## §11 ภาษาไทยเพี้ยน / อิโมจิหาย

### 11.1 ภาษาไทยขึ้นเป็น ??? หรือ à¸
| จุดที่ต้องตรง | ค่า |
|---|---|
| Collation ฐานข้อมูล | `utf8mb4_unicode_ci` |

ALTER DATABASE affiliatehub

ต้องเป็น `utf8mb4` เท่านั้น (`utf8` ธรรมดาเก็บอิโมจิไม่ได้)

## §12 เมื่อแก้ไม่ได้ — ข้อมูลที่ต้องส่งให้แอดมิน

ส่งครบทั้ง 7 ข้อนี้จะแก้ได้เร็วที่สุด:

1. **หน้าที่เกิดปัญหา** — ชื่อเมนูจริงที่กด
2. **สิ่งที่ทำก่อนเกิด** — ทีละขั้น
3. **ข้อความ error เต็ม ๆ** — ก๊อปมาทั้งบรรทัด ไม่ต้องสรุป
4. **ภาพหน้าจอ** — ให้เห็นทั้งหน้า
5. **ระบบปฏิบัติการและเบราว์เซอร์**
6. **URL ที่เปิดอยู่**
7. **Log ล่าสุด** — `apache/logs/error.log` บรรทัดท้าย ๆ

> ⚠️ **ห้ามส่ง** API Key, รหัสผ่าน หรือ Token จริงในภาพหน้าจอ — ปิดทับก่อนส่งเสมอ
